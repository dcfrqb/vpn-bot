# Релиз 3.0

Одноразовые платежи через ЮKassa сохранены. Реальная платежная приемка проводится
владельцем после развертывания. Панель Remnawave этим релизом не обновляется.

## Временно отключено

Новые платежи Telegram Stars полностью отключены: цены и кнопки Stars не показываются,
новые счета не создаются, pre-checkout отклоняется. `STARS_ENABLED` принудительно
остается `false`, включая старое значение `true` в окружении. Код интеграции,
обработка уже прошедших платежей и возвратов сохранены.

Автопродление и привязка карт для новых автоплатежей временно отключены до запуска сайта.
Новые покупки не предлагают автопродление и не запрашивают сохранение способа оплаты.
Фоновая задача повторных списаний выключена. Старые кнопки включения и справки
показывают сообщение о временной недоступности; отключение ранее включенного
автопродления остается доступным.

Конфигурация принудительно устанавливает `AUTOPAY_ENABLED=false` и
`TASK_AUTOPAY_ENABLED=false`, включая случай старых значений `true` в окружении.
Существующие записи платежей и сохраненных способов оплаты не удаляются,
оплаченный срок подписок не меняется.

Возврат функции требует отдельного изменения после запуска сайта, согласования
с ЮKassa, проверки платежного сценария и приемки привязки, списаний, отказов и отключения.
Появление сайта само по себе функцию не включает.

## Интерфейс

Короткие результаты нажатий показываются системными окнами Telegram с кнопкой OK.
Текстовые блоки разделены одной пустой строкой. Длинные инструкции обновляют карточку
чата без обрезки. В ошибках промокодов отображается введенный код, а не тестовый пример.
Обращения к пользователям и инструкции используют форму «вы».

## Исправления после 3.0.0

Подтверждение оплаты заменяет исходную карточку с кнопкой «Оплатить». Привязка
карточки сохраняется в метаданных платежа и доступна webhook, ручной проверке
и восстановлению после перезапуска. Повторная проверка показывает короткое
системное окно, сохраняя карточку с результатом, подключением и возвратом.

Если исходное сообщение удалено или его нельзя редактировать, подтверждение
приходит отдельным сообщением. При сетевой неопределенности доставка повторяет
редактирование вместо отправки возможного дубля. Для старых платежей без
привязки сообщения сохранено прежнее поведение. В порт `Notifier.notify_user`
добавлен необязательный параметр `edit_message_id=None`.

Триал и промокоды с кнопок показывают короткий результат системным окном,
успешная активация обновляет профиль. Введенный текстом промокод и повторная
команда обновляют текущую карточку: Telegram не поддерживает alert без callback.
Текущая карточка запоминается в Redis отдельно для бота, чата и пользователя.
Если она удалена или Redis недоступен, остается резервная отправка сообщения.

Решение по возврату и повторная доставка после сбоя редактируют сохраненную
карточку заявки. Отдельное сообщение остается резервом для старых записей
без message_id или недоступной карточки. Служебный отчет о собственной активации
промокода не дублируется администратору в личку; другие администраторы и
отдельный административный чат сохраняют уведомления. Для этого в
`Notifier.notify_admins` добавлен необязательный `exclude_telegram_id=None`.
