# Экраны бота 3.0: типы и как они собираются

Любой экран и любое сообщение бота относится к одному из 12 типов. Тип задает раскладку текста
и клавиатуры, экран задает только содержимое (заголовок, строки, кнопки). Поменял тип: поменялись
все экраны этого типа. Рисовать экран руками (свои переносы, свои эмодзи, свое место для кнопки
«Назад») нельзя.

Код:

| Слой | Файл | Что там |
|---|---|---|
| Словарь | `src/app/domain/texts/ui.py` (`E`, `B`) | все эмодзи и подписи кнопок, одно место |
| Раскладка текста | `src/app/domain/texts/ui.py` (`Screen`, `Block`, строители типов) | чистые функции, без aiogram: ими пользуются и сервисы (пуши) |
| Раскладка клавиатуры | `src/app/bot/views/kit.py` (`keyboard`, `view`, `Footer`) | порядок рядов, футер, пары |
| Содержимое экранов | `src/app/domain/texts/<раздел>.py` | функции `*_screen(...) -> Screen`: заголовки, строки, подсказки |
| Сборка экрана | `src/app/bot/views/<раздел>.py` | `Screen` + кнопки через `kit.view(...)` |

Каталог для владельца: `Servers/docs/РЕВЬЮ_БОТА_2026-09-23/ЭКРАНЫ_3.0.md`, собирается
`scripts/render_screens_catalog.py` из этого же кода.

## Общие правила текста

1. Заголовок: `{эмодзи} <b>{Заголовок}</b>`. Эмодзи вне `<b>`, без двоеточия в конце.
2. Тело: блоки. Блок = необязательная строка-подзаголовок (`{эмодзи} <b>{подзаголовок}</b>`) и
   под ней `<blockquote>` со строками. Строки данных пишутся как `Метка: значение`.
3. Первый блок без подзаголовка прилипает к заголовку экрана (сразу на следующей строке, как в 2.1.1).
   Все остальные части разделены ровно одной пустой строкой.
4. Подсказка (что нажать дальше, мелкое пояснение) идет последней строкой, курсивом `<i>...</i>`.
5. Блок без цитаты (`quote=False`) нужен только для ссылки `<code>...</code>` и юридической строки.
6. Разделители `———`, двойные пустые строки, эмодзи внутри `<b>` не используются.
7. Все подставленные значения проходят через `h()`; числа и даты через `fmt_rub`, `fmt_date_msk`,
   `days_ru`, `months_ru`, `fmt_gb`. Текст на «вы», без буквы «ё», без длинного тире.

## Системные окна результатов кнопок

Короткий результат нажатия показывается через `answerCallbackQuery` с `show_alert=True`.
По [Telegram Bot API](https://core.telegram.org/bots/api#answercallbackquery), поле `text`
ограничено 200 символами; параметры `parse_mode` и `entities` отсутствуют.
В окне используются обычный текст, переносы строк и обычные эмодзи. Жирный шрифт,
курсив, цитаты, моноширинный текст, HTML, Markdown и текстовые ссылки с разметкой
недоступны. Вид окна и стандартной кнопки OK определяет клиент Telegram;
собственные кнопки и оформление к этому ответу не добавляются.

`show_result` снимает HTML-разметку исходного экрана и разделяет непустые строки
одной пустой строкой. Начальные, конечные и повторные пустые строки убираются.
Результат длиннее 200 символов с учетом отступов обновляет исходную карточку без обрезки.
Ссылки и инструкции с форматированием следует оставлять в карточках чата.

## Общие правила клавиатуры

Порядок рядов всегда один (`kit.keyboard`):

1. `primary`: главное действие экрана, всегда первое (Оплатить, Подключиться, Продлить).
2. `options`: варианты выбора, по одному в ряд (тарифы, сроки, пакеты, устройства).
3. `secondary`: второстепенные действия, по одному в ряд.
4. `links`: кнопки-ссылки (инструкция, поддержка, оферта), по одному в ряд.
5. Футер.

Пара кнопок в одном ряду только там, где это объявлено: `[🔄 Обновить] [ℹ️ Помощь]` в меню,
`[✅ Да] [✖️ Отмена]` в подтверждении, `[⬅️ Назад] [🏠 В меню]` в футере, решение админа
`[✅ ...] [❌ ...]`, листалка `[⬅️] [➡️]`, номерные кнопки списка `[❌ 1] [❌ 2] [❌ 3]`
(`kit.grid`: до 4 в ряд, ряды выровнены: 5 = 3+2, 6 = 3+3, 7 = 4+3).

Футер (`kit.Footer`):

| Где экран | Футер |
|---|---|
| Главное меню (корень) | нет |
| Экран первого уровня (открыт из меню) | `[🏠 В меню]` |
| Экран второго уровня и глубже | `[⬅️ Назад] [🏠 В меню]` |
| Пуш, всплывашка | нет |
| Главный экран админки | `[🏠 В меню]` |
| Экран админки | `[👑 В админку]` или `[⬅️ Назад] [👑 В админку]` (`Footer.back_admin`) |
| Шаг мастера админки (рассылка) | `[⬅️ Назад]` на прошлый шаг (кроме первого шага), затем `[✖️ Отменить рассылку] [👑 В админку]` (`Footer.wizard`) |

У каждого экрана админки есть путь в админку: ответы на команды, ошибки и справки по командам
тоже идут с `[👑 В админку]`. «👑 В админку» из мастера бросает черновик (состояние мастера
очищается). `/cancel` в мастере работает как «✖️ Отменить рассылку».

## Типы

### 1. `status` Карточка статуса

Главное меню. Нет общего заголовка: карточка состоит из разделов.

```
👤 <b>Профиль</b>
<blockquote>ID: {id}
Имя: {name}</blockquote>

{статус} <b>{Подписка активна | Льготный период | Подписка истекла | Подписка не оформлена}</b>
<blockquote>{Метка: значение, 1-4 строки}</blockquote>

🛡 <b>Обход блокировок</b>          (только Pro)
<blockquote>{Использовано: X из Y | Ссылка готовится...}</blockquote>

<i>{подсказка: пробный период / данные устарели}</i>
```

Кнопки: `🚀 Подключиться`, `🎁 Попробовать 5 дней бесплатно` (если доступно), `💳 Подписка`,
`📱 Мои устройства`, `[🔄 Обновить] [ℹ️ Помощь]`, `👑 Админ-панель` (админам). Футера нет.

### 2. `choice` Выбор

Тарифы, сроки, пакеты обхода, тарифы подарка.

```
{эмодзи} <b>{Заголовок}</b>
<blockquote>{вводная или описание, 1-6 строк}</blockquote>      (необязательно)

{эмодзи} <b>{Вариант}</b> · {цена} · {метка}           (0..n; цена и метка необязательны)
<blockquote>{только то, чем вариант отличается}</blockquote>

<i>{общее для всех вариантов | Выберите ... кнопкой ниже}</i>
```

Кнопки: варианты (`Название · цена`), затем доп. действия, футер. Сроки и пакеты по одному в ряд,
тарифы по два в ряд (`kit.grid(per_row=2)`). В списке тарифов «🎁 Подарить» стоит в ряду футера
перед «🏠 В меню» (`Footer.to_menu(lead=...)`).

Список тарифов (`pay.plans`): компактные карточки, в них только отличия.

```
💳 <b>Тарифы CRS VPN</b>

🟢 <b>Lite</b> · от 129 ₽/мес
<blockquote>🇫🇮 🇳🇱 · 3 устройства</blockquote>

🔵 <b>Standard</b> · от 249 ₽/мес · ⭐ выбирают чаще
<blockquote>🇳🇱 🇫🇮 🇩🇪 · 5 устройств</blockquote>

💎 <b>Pro</b> · от 449 ₽/мес
<blockquote>🇳🇱 🇫🇮 🇩🇪 🇺🇸 · 10 устройств
🛡 Обход блокировок 150 ГБ/мес</blockquote>

<i>Основной VPN во всех тарифах без ограничения трафика. Обход в Pro: {obhod_gb} ГБ в месяц. При оплате за год экономия до {N}% по сравнению с помесячной оплатой.</i>
```

Кнопки: `[🟢 Lite · 129 ₽] [🔵 Standard · 249 ₽]`, `[💎 Pro · 449 ₽]`, `[🎁 Подарить] [🏠 В меню]`.

Тариф (`pay.periods`, после нажатия на тариф): описание целиком и сроки.

```
💎 <b>Pro</b>
<blockquote>🇳🇱 Нидерланды
🇫🇮 Финляндия
🇩🇪 Германия
🇺🇸 США
📱 До 10 устройств
♾ Основной VPN без ограничения трафика</blockquote>

🛡 <b>Обход блокировок</b>                                 (только тарифы с обходом)
<blockquote>Отдельная ссылка через российский вход для мобильного интернета с белыми списками, 150 ГБ в месяц.</blockquote>

<i>Выберите срок кнопкой ниже.</i>
```

Кнопки: сроки по одному в ряд `{срок} · {цена} ({минус}N%)` (выгода от цены за 1 месяц, знак U+2212),
футер `[⬅️ Назад] [🏠 В меню]` (Назад ведет в список).

Цифры не пишутся руками: все берется из каталога `src/app/domain/plans.py`. Карточку списка дает
`get_plan_card` (флаги стран в порядке тарифа, устройства, обход, флаг `popular` для метки
«⭐ выбирают чаще»), описание тарифа собирает `build_plan_features`, «до N%» считает
`max_yearly_saving_percent` по ценам тарифов списка, «от ... ₽/мес» это цена за 1 месяц. Названий
стран в списке нет, только флаги. В списке тарифов три тарифа меню; старый тариф (Базовый, Премиум)
добавляется последним только тому, у кого это текущая оплаченная подписка (не бессрочная, без
сквадов `-m`, `-friend`, `arcadia`). Список подарка устроен так же, с вводной про ссылку для друга.

### 3. `checkout` Оплата

Счет перед оплатой.

```
💳 <b>Оплата</b>
<blockquote>Тариф: {plan}
Срок: {months}
К оплате: {price}
Автопродление: {включено | выключено}</blockquote>

<i>{как оплатить и что будет после}</i>

<i>Нажимая «Оплатить», вы принимаете условия <a href="{offer}">оферты</a> и <a href="{privacy}">политики конфиденциальности</a>.</i>
```

Кнопки: `💳 Оплатить {price}` (ссылка ЮKassa) первой, `⭐ Оплатить звездами`, переключатель
автопродления, `🔄 Проверить оплату`, футер `[⬅️ Назад] [🏠 В меню]`.

### 4. `result` Результат

Ответ на нажатие: успех, ожидание, предупреждение, ошибка, справка. Эмодзи заголовка задается видом:
`ok` ✅, `wait` ⏳, `info` ℹ️, `warn` ⚠️, `error` ❌.

```
{вид} <b>{Заголовок}</b>
<blockquote>{1-3 строки или Метка: значение}</blockquote>

<i>{что делать дальше}</i>
```

Кнопки: 0-2 действия (главное первым), затем футер.

### 5. `article` Инструкция

Подключение и помощь: несколько смысловых разделов.

```
{эмодзи} <b>{Заголовок}</b>

{эмодзи} <b>{Раздел}</b>
<blockquote>{текст раздела}</blockquote>

{эмодзи} <b>{Раздел со ссылкой}</b>
<code>{ссылка}</code>

<i>{подсказка}</i>
```

Кнопки: ссылки (открыть ссылку, инструкция, поддержка), действия, футер.

### 6. `items` Список

Мои устройства (и любые будущие списки у пользователя). Два вида: строки (`lines`, один элемент в
строке, одна цитата) или карточки (`cards`, у каждого элемента своя цитата с номером, `ui.card`).

```
{эмодзи} <b>{Заголовок} ({n} из {limit})</b>
<blockquote>{иконка} <b>1. {имя}</b>
{платформа и версия ОС} · {приложение и версия}
Добавлено: {дата}
Онлайн: {сегодня | вчера | N дней назад}
⚠️ Давно не выходило на связь              (молчит больше 30 дней)</blockquote>

<blockquote>{иконка} <b>2. {имя}</b>
...</blockquote>

<i>{что можно сделать со списком}</i>
```

Пустой список: та же раскладка, в цитате одна строка «пока пусто».

Устройства: карточки по последнему выходу на связь (свежие сверху), даты по МСК. Имя одно на
карточку, кнопку и подтверждение: модель, иначе ОС и платформа, иначе приложение (из User-Agent),
иначе «Устройство N». Кнопки: номерные `❌ N` (номер = номер карточки) сеткой `kit.grid`, дальше
прочее, футер `[🏠 В меню]`. Нажатие `❌ N` открывает подтверждение «Отвязать {имя}?». Если
отвязывание выключено флагом `DEVICES_UNLINK_ENABLED`, номерных кнопок нет, подсказка про
поддержку и кнопка `✍️ Поддержка`.

### 7. `confirm` Подтверждение

```
❓ <b>{Вопрос?}</b>
<blockquote>{последствия}</blockquote>
```

Кнопки: один ряд `[✅ Да, {действие}] [✖️ Отмена]`. Футера нет (Отмена и есть выход).

### 8. `prompt` Ввод

Бот ждет сообщение от пользователя.

```
✍️ <b>{Что прислать}</b>
<blockquote>{как прислать}</blockquote>

<i>Отмена: /cancel</i>
```

Кнопки: футер `[🏠 В меню]`.

### 9. `push` Уведомление

Сообщение, которое бот присылает сам: оплата прошла, напоминание, новое устройство, возврат.
Раскладка как у `result`, но заголовок задается своим эмодзи, а футера нет.

```
{эмодзи} <b>{Заголовок}</b>
<blockquote>{1-3 строки или Метка: значение}</blockquote>

<i>{что делать дальше}</i>
```

Кнопки: 0-2 действия, без футера. Отправляется как HTML.

### 10. `toast` Всплывашка

Ответ на кнопку над чатом (`callback.answer`). Обычный текст без тегов, до 200 символов, одно-два
предложения. Эмодзи в начале только для вида (⏳ ждать, ✅ готово). Константы лежат в модулях текстов.

### 11. `admin_screen` Экран админки

Карточка или таблица в админке.

```
{эмодзи} <b>{Заголовок}</b>
<blockquote>{Метка: значение}</blockquote>

{эмодзи} <b>{Раздел}</b>
<blockquote>{строки или элементы списка}</blockquote>

<i>{команды или подсказка}</i>
```

Кнопки: действия, листалка `[⬅️] [➡️]`, футер `[👑 В админку]` или `[⬅️ Назад] [👑 В админку]`.

### 12. `admin_alert` Алерт админам

```
{эмодзи} <b>{Событие}</b>
<blockquote>👤 {имя} @{username}
🆔 {id}</blockquote>

<blockquote>{Метка: значение}</blockquote>

<i>{что сделать админу}</i>
```

Кнопки: решение одним рядом `[✅ ...] [❌ ...]`, иначе нет.

## Словарь

Все подписи и эмодзи берутся из `domain/texts/ui.py`. Одна вещь называется одинаково везде.

| Понятие | Кнопка / слово | Где |
|---|---|---|
| Подключение | `🚀 Подключиться` | меню, пуши после оплаты, промо |
| Подписка, тарифы | `💳 Подписка` | меню, ошибки оплаты |
| Продление | `💳 Продлить подписку` | напоминания, льготный период |
| Оплата | `💳 Оплатить {price}` | оплата |
| Проверка оплаты | `🔄 Проверить оплату` | оплата |
| Звезды | `⭐ Оплатить звездами ({n})` | оплата |
| Автопродление | `🔁 Включить автопродление` / `🔁 Без автопродления` / `🔁 Отключить автопродление` | оплата, пуш |
| Устройства | `📱 Мои устройства` | меню, пуш |
| Обход | «Обход блокировок», кнопка `➕ Докупить обход` | подключение, пуш, меню |
| Ссылки | `🔗 Открыть основную ссылку`, `🛡 Открыть ссылку обхода` | подключение |
| Инструкция | `📖 Инструкция` | подключение, пуш |
| Поддержка | `✍️ Поддержка` | везде, где есть ошибка |
| Пробный период | `🎁 Попробовать 5 дней бесплатно` | меню, подключение |
| Подарок | `🎁 Подарить` (в ряду с `🏠 В меню`) | тарифы |
| Возврат | `↩️ Не смог подключиться` | пуш после оплаты |
| Обновить | `🔄 Обновить` | меню, подключение |
| Помощь | `ℹ️ Помощь` | меню |
| Назад | `⬅️ Назад` | на экран выше |
| В меню | `🏠 В меню` | в главное меню |
| Админка | `👑 Админ-панель`, `👑 В админку` | админы |
| Отвязать устройство | `❌ {номер карточки}` | мои устройства |
| Отменить мастер | `✖️ Отменить рассылку` | мастер рассылки |

Эмодзи статусов: `✅` готово, `⏳` ждем, `ℹ️` справка, `⚠️` внимание, `❌` ошибка;
подписка: `🟢` активна, `🟡` льготный период, `🔴` истекла, `💡` не оформлена.
Эмодзи разделов: `👤` профиль, `🛡` обход, `📱` устройства, `🔗` ссылка, `💡` как подключить,
`💳` оплата, `🎁` подарок и пробный период, `🎉` промокод, `↩️` возврат, `🔁` автопродление,
`🔒` доступ закрыт, `❓` вопрос, `✍️` ввод.

## Как добавить экран

1. Выбери тип. Если ни один не подходит, сначала обсуди новый тип, не рисуй экран руками.
2. В `domain/texts/<раздел>.py` напиши функцию `..._screen(...) -> Screen` через строитель типа
   (`ui.result(...)`, `ui.choice(...)`...). Только слова и данные.
3. В `bot/views/<раздел>.py` собери `kit.view(screen, primary=..., footer=...)`.
4. Добавь экран в `scripts/render_screens_catalog.py` и перегенерируй каталог.
5. `pytest tests/ui` проверяет правила раскладки (теги закрыты, нет `ё`, нет длинного тире, тост до 200
   символов, футер на месте).

### Подтверждение пробного периода

После кнопки «Попробовать 5 дней бесплатно» успешная активация подтверждается нативным диалогом Telegram (`answerCallbackQuery`, `show_alert=True`) с кнопкой OK: «🎁 Пробный период активирован\nТариф: Standard на 5 дней.». Диалог содержит обычный текст, без HTML. За ним обновляется экран подключения. Если callback просрочен, подтверждение приходит отдельным сообщением, выдача повторно не запускается. Административное уведомление о промокоде остается отдельным служебным событием.

### Результаты нажатия кнопок

Короткие результаты (до 200 символов обычного текста) показываются нативным диалогом Telegram с кнопкой OK через `show_result`. HTML превращается в обычный текст с сохранением строк. Более длинные объяснения и экраны с выбором редактируют исходное сообщение через `render`, без обрезки текста. После диалога состояние меню, оплаты или списка устройств обновляется в том же сообщении при необходимости. При просроченном callback редактируется исходный экран, бизнес-операция повторно не запускается. Новое сообщение допускается как запасной путь, если исходное сообщение недоступно или не подлежит редактированию.

Ответы на текстовые команды и ввод, счета, ссылки, фоновые уведомления об оплате, решении по возврату, сроках подписки и события для администраторов остаются сообщениями: они не имеют актуального callback. Перевод представления не меняет платежи, выдачу доступа или фоновые задания.
